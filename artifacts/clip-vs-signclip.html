Two grounding scorers, two different answers

CLIP and SignCLIP are both zero-shot vision-language scorers used elsewhere in this project as an "independent" stand-in for which body region a cue word should ground to. We ran both on the same 300 test sentences, the same spaCy-extracted cue phrases, and — as region definitions were split progressively finer, four times over — the same eight body regions. At every granularity we tried, the two scorers agree with each other no more than chance would predict.

Splitting regions finer doesn't close the gap

Same 2,817 phrase-level decisions, re-scored four times as the shared region set went from 4 lumped regions to 6 (splitting "face" into mouth/eyes/face-outline) to 7 (adding "shoulder" alongside "body") to 8 (adding "torso" — "body" minus the wrist/fingertip points MediaPipe's own pose skeleton already carries). The excess over chance stays essentially flat throughout — this isn't a resolution problem.

Scorers & methodology

Scorers compared

CLIP (openai/clip-vit-base-patch32): scores region-CROPPED pixels per frame against text, argmax over frames after subtracting each frame's mean similarity across phrases (removes generic "attractor" frames). SignCLIP (SignCLIP-multilingual, pretrained on Spreadthesign — never trained on How2Sign): scores a MediaPipe-Holistic pose sequence with all but one landmark group/point-subset zeroed, one call per region, same baseline correction applied per-sequence.

Cue phrases

spaCy noun-chunks + verb lemmas (grounding.cue_extraction.extract_cue_phrases) on the ground-truth sentence text — identical extraction for both scorers, verified to produce byte-identical phrase lists per sentence (0 mismatches across 300 sentences).

Region definitions

body
CLIP: bbox over shoulders+hips — visually CONTAINS the hands whenever they're held in front of the torso (most of continuous signing). SignCLIP: whole POSE_LANDMARKS (33-point skeleton) — which itself already includes both wrists plus a coarse pinky/index/thumb fingertip estimate per side, independent of the separate, much more detailed 21-point hand-landmark groups. Neither "body" is a clean hand-free control.
torso
An ADDITIONAL probe, added alongside "body" (not replacing it) once the above was noticed. CLIP: the same body bbox, but with left_hand/right_hand boxes blacked out first — same recipe as face_oval. SignCLIP: POSE_LANDMARKS with both wrists and both sides' pinky/index/thumb points zeroed. Both scorers score it slightly lower than "body" — consistent with those extra points carrying real, if coarse, hand information.
shoulder
An ADDITIONAL probe on both sides, not carved out of "body" — CLIP: bbox over LEFT/RIGHT_SHOULDER only. SignCLIP: POSE_LANDMARKS masked to LEFT/RIGHT_SHOULDER only. The two overlap with "body" by design on both sides, mirroring how region_extractor.py already treats them.
eyes / mouth / face_oval
CLIP: separate landmark-derived bboxes; face_oval's box has eyes+mouth bboxes blacked out first so it doesn't just re-show them inside a bigger rectangle. SignCLIP: a strict, non-overlapping 128-point partition of its face input (40 mouth / 52 eyes+eyebrows / 36 outline points) — verified exhaustive, zero overlap.
left_hand / right_hand
Bbox / full hand landmark group respectively — the one region pair that's a genuinely close match between the two scorers.

No "nose": SignCLIP's face input is MediaPipe's 128-point contour set, which structurally contains zero of mediapipe's own FACEMESH_NOSE points — there is no way to isolate a nose signal from this model's input at all, so CLIP's nose region is excluded from every comparison here.
